## v41.30 (review follow-up: stale test, deploy order, clean-up)
- **Strict viewing time is opt-in per page.** The server counts viewing time only for a page that opens the step with `hb: true` (every v41.26+ page does). A page on an older version keeps the wall-clock rule, so it no longer matters whether the site or the function is deployed first.
- **Weekend days apply everywhere.** `Progress.configure(state)` runs at the start of every render, so essential-training deadlines and new assignments use the setting.
- **Essential training uses the organisation's date** (overdue, working days left, assigned-on) through `Progress.today()`.
- **Dead code removed:** `permRows`, `goAdminHome`, `toggleLgDemo`, `toggleSearch`, `setGq`. `exportUsers` is used by the Export menu and stays.
- Tests: `learning-core.test.js` survey test now expects the refusal of `<` and `>`; `ui-v41_30.test.js` runs the edited front-end files as they are.

## v41.29 (weekend days, one download helper)
- **Weekend days are a setting** (Master data › App settings › Weekend days, default Saturday + Sunday, at least one working day must remain), stored in `platform.defaults.weekendDays`. Batch training days and the holiday list check keep their own rules.
- **One download helper:** `downloadBlob()` in helpers.js; `csvDownload` and the database backup use it.
- `TODAY_KEY` replaced by `Progress.today()` in platform.js, masters.js, database.js and `defaultDue`.
- Tools: `scripts/prune-dist.mjs`, `scripts/check-unbound.mjs`, `scripts/check-callers.mjs`, `scripts/find-duplicates.mjs`.

## v41.28 (today in the organisation's time zone)
- `Progress.today()`: the organisation's date when connected (ORG_TIMEZONE, default Asia/Kolkata), `TODAY_KEY` on the offline demo. Overdue, completion and start fallbacks, default due dates, the migration report end date, the first admin's joined date and the account-expiry check use it.

## v41.27 (unnecessary API calls)
- Opening a saved sign-in is one call: no `auth.getUser()`; "must change password" comes from the token; `me` records the sign-in when asked.
- One database call instead of four for every `learning` request (`sf_learning_ctx`, migration 011); falls back to the four reads without it.
- Rows load one collection at a time, six at once; the learner directory loads in parallel; learners ask to sign only files that can qualify. `LOAD_DEBUG: true` in config.js logs rows and time per collection.

## v41.26 (reviewer findings)
- **Submit can be finished by a retry**; attempts handed in before v41.26 count as complete.
- **Viewing time is counted by the server** (`stepPing` heartbeat; `SEAT_TIME_STRICT=false` restores the old rule).
- **A pass follows the attempts' current results** (a lower re-rating can remove it); steps finished another way are never touched.
- **No invented assignment dates:** a missing assigned-on date is "date unknown".
- **`<` and `>` are refused with a message** instead of being removed silently.
- **One lifetime for file links** (`SIGNED_URL_TTL_SECONDS`, default 3600), renewed in the background; **save retry backs off** (8 s to 5 minutes, stops after 10 failures).

## v41.24
- **Certificates moves into Master data (admins only).** The tile moves from Learning content to Master data (after Badges), the separate Certificates permission is removed (the screen needs the Master data permission) and Master data gets a Certificates tab. A custom role that had the old Certificates permission can no longer open the screen. Test: `tests/e2e/v41_24_e2e.py`.
